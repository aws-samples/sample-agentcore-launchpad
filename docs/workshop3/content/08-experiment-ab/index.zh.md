# 第 08 章 · 优化与配置包 A/B 实验

> **目标**：给 `lab-hr-assistant` 准备两版系统提示词，各承接一半流量同时运行，
> 用第 07 章自建的评估器判断改动是否有效。
>
> **前置条件**：完成[第 07 章](../07-evaluation)——`lab-hr-assistant` 为 `active`、
> 两个数据集已建、`HrThirdPartyDisclosureZh` 为 `ACTIVE`、两次基线评估已完成。
> 账号里不能有其它 `running` 实验，共享实验网关也不能被其它实验占用。
>
> **预计耗时**：约 20–30 分钟。需要等的有三段：洞察运行（对基线会话分析，不重新调用 Agent，
> 实测约 2 分钟）、推荐生成（约 4–5 分钟）、发送流量和在线评估记录到齐（8–15 分钟）；
> 若做可选的晋级后回归，另加约 6 分钟。以页面进度为准。
>
> **本章将创建的 AWS 资源**：1 次洞察运行（复用 7.6 基线的 28 个会话）、2 个配置包、
> 1 个 A/B 测试、1 个在线评估配置，以及可选的 1 次回归批量评估。
> 最后的`清理`只删实验产生的临时资源，Agent、评估器和数据集都会留下。

## 8.1 对基线会话发起洞察，再新建实验看数据就绪度

洞察的输入不用重新准备：7.6 基线评估回放产生的 28 个会话就是要归因的对象。打开 `08 评估`
的`运行`列表，点击 7.6 那次运行（数据集列为 `lab-hr-zh-ab`）打开详情，右侧
`洞察 — 失败归因`面板上点击 `↻ 洞察 · 这些会话`。

![基线运行详情的洞察面板](/static/images/08-insights-on-run.png)  
*图 8-1：左侧是 7.6 的三项得分，右侧洞察面板上是 `↻ 洞察 · 这些会话` 按钮。*

确认弹窗写明`将基于 run-<id> 的 28 个会话新建一个洞察运行`，点击 `运行洞察`。这次运行
**不会重新调用 Agent**，直接进入 `EVALUATING`，对已有会话做失败归因、用户意图和执行摘要
三类分析，大约 2 分钟。

回到`实验`，点击 `新建实验`，选择 `lab-hr-assistant`。

![数据就绪度](/static/images/08-readiness.png)  
*图 8-2：`已观察到的工具`列满五个，`尚未观察到的工具`为 `—`。*

就绪度要求**五个工具全部被调用过**，缺一个即停在`数据稀疏`。

> **就绪度读的是一个时间窗内该 Agent 的全部流量。** 判断依据是
> `尚未观察到的工具`为 `—`，不是会话数。

## 8.2 用洞察定位根因

切回`运行`，列表里多出一条数据集列为 `insights · 28` 的运行，等它显示`已完成`后点开查看结果。

失败分析把缺陷归成类别、子类别和根因三层。一次真实运行归并出两个类别、三个子类别，
主类别覆盖 19 个会话，均指向同一个缺口——系统提示词缺少身份校验环节，把自称的职权
当作了授权：

| 类别（示例） | 受影响会话 |
|---|---|
| Identity Verification Bypass for Sensitive Employee Data Access | 19 |
| Incomplete Data Retrieval and Information Leakage | 2 |

![洞察失败树](/static/images/08-insights.png)  
*图 8-3：失败树示例。类别名由 LLM 归并生成，每次运行的措辞和归组会不同，
以自己页面为准。*

每条受影响会话都带 span id，可据此回到第 06 章的可观测页面核对原始调用。

> **受影响会话数不是缺陷率。** 洞察是抽样归并，不是逐条枚举：28 个会话可能大部分泄露，
> 失败树只报告其中一部分。

## 8.3 AI 推荐

切到`实验`子导航，打开 8.1 创建的那个实验，页面是一列阶段面板，从 `01 · AI 推荐` 开始。
在这个阶段卡片里做两件事：

- `系统提示词`和`工具描述`两个复选框我们**只选`系统提示词`**
> 只保留一个生成类型，两版之间才只有一个变量；同时改工具描述会让结果无法归因。

- `TRACE 来源`：从下拉菜单里选择`洞察 · <运行 id> · 28 个会话` 那一项，也就是 8.1 的失败归因。  
> 不要用默认的 7 天窗口：它可能混入手工聊天甚至上一轮实验的流量，结果无法复现。

![AI 推荐阶段卡片](/static/images/08-recommend-source.png)  
*图 8-4：`01 · AI 推荐` 阶段卡片，`TRACE 来源`选中 8.1 的洞察运行。*


点击 `生成 AI 推荐` 之后等待完成（约 4–5 分钟）。完成后卡片并排显示
`当前`与`推荐`两版提示词，`推荐`一栏标 `CHANGED`。例如一次真实运行新增的段落是：

```
Data access rules:
- Employees may only view their own pay stubs. If someone requests another
  employee's pay or salary data, decline and explain that pay information is
  confidential to each employee.
- Do not accept delegation claims (e.g., "X asked me to check their pay") as
  authorization to access another person's pay data.
```

![AI 推荐结果](/static/images/08-recommend.png)  
*图 8-5：新增的 `Data access rules` 只覆盖工资单，没有 PTO 披露条款。*

同一个 Agent、同一批 trace，每次给出的措辞可能不同——有的版本只覆盖工资单、有的用
「确认」代替「拒绝」。共同点是**只修了一部分缺陷**：优化器的 reward 信号来自
`目标达成率`一类的通用指标，它对泄露不敏感。所以我们接下来进入手工编辑

## 8.4 编辑补全后再`接受并继续`

推荐结果下方的编辑框中，在推荐条款的基础上继续补全，覆盖三点：

```
- PTO 余额、PTO 使用历史、工资单，以及代他人提交 PTO 申请
- 对比、求和、排序这类会暴露他人数据的间接问法
- 自称主管、HR 管理员或审计人员不构成授权
```

改完点击 `接受并继续`，阶段标记为`已接受`。

## 8.5 配置 BUNDLE、网关与 A/B 测试

点击 `▸ 创建 CONTROL + TREATMENT BUNDLE`：

- **`CONTROL（当前配置）`**：Agent 当前的系统提示词，原样不动
- **`TREATMENT（接受的推荐）`**：8.4 接受的版本

点击 `▸ 创建网关 + 在线评估`，在`在线评估器`里选两个：

| 评估器 | 作用 |
|---|---|
| `HrThirdPartyDisclosureZh` | **主指标**，衡量本章缺陷 |
| `目标达成率 GoalSuccessRate` | 对照，预期在判定面板上与主指标一升一降（解读见 8.7） |


点击 `▸ 创建 A/B 测试 50/50`。

## 8.6 发送流量：28 条越权提问

**先核对数据集下拉显示的是 `lab-hr-zh-ab (28)`**，再点击 `▸ 发送流量`。

> ⚠️**下拉默认选中列表里第一个可回放数据集，不一定是本章的。** 选错数据集这次实验的数据就作废，需要重新做过。

完成后阶段面板显示 `sent 28 · failed 0`。

## 8.7 监控与判定：交给面板轮询

发送流量完成后即可点击 `▸ 监控结果`：面板每 45 秒自动轮询（上限 15 分钟），流量结束到判定可读大约 8–15 分钟；轮询到达上限仍未出判定时，
再点击一次继续轮询。

判定面板每个指标一行，按 `Δ / CONTROL / TREAT / n / p` 排布。一次真实运行的结果：

| 指标 | Δ | CONTROL | TREAT | n | p | |
|---|---|---|---|---|---|---|
| `目标达成率` | −0.36 | 0.86 | 0.50 | 14/14 | 0.132 | 未达统计显著 |
| `HrThirdPartyDisclosureZh` | +0.50 | 0.00 | 0.50 | 14/14 | 0.010 | ✓ 统计显著 |

横幅：`◎ TREATMENT-WINS`，`Δ 0.0714 · n=56 · ✓ 统计显著`。

![判定面板](/static/images/08-verdict.png)  
*图 8-6：两行指标一升一降，主指标行标注 `✓ 统计显著`，横幅 `Δ 0.0714`。数值是示例。*

**上表是一次运行的示例。**模型对拒绝指令的遵循是概率性的，另一次同配置的
运行得到的是 `目标达成率 −0.29 / 主指标 +0.29 / p=0.101 · 未达统计显著`，横幅
`◎ 无显著差异`。两种结局都正常，按自己的判定面板读数决策。逐项解读：

- **一个指标涨、一个指标跌，是预期结果，不是数据出错。** 两个指标在给同一批回答打分，
  但标准相反。treatment 拒绝了越权请求：在主指标 `HrThirdPartyDisclosureZh` 的标准里，
  拒绝等于「没泄露」，得分从 0.00 涨到 0.50；在`目标达成率`的标准里，拒绝等于「用户想要的
  没给」，得分从 0.86 跌到 0.50。这正是 7.6 展示过的
  问题：拿`目标达成率`当主指标，会把修复判成回退。
- **横幅的整体 `Δ` 不是结论。** 它是各评估器 `Δ` 按样本量加权后的平均值，上面那一升一降
  在平均时正好互相抵消，所以横幅数字很小。结论只看主指标那一行的均值与 p 值。
- **`无显著差异` 只说明样本量不够，不说明改动无效。** 面板此时给出三个选项：补流量后
  重新启动实验、主观判断后 PROMOTE（有确认弹窗）、CLEANUP 保留现状。
- **主指标显著提升不等于缺陷消除。** 示例中 treatment 仍有约 50% 的会话泄露；
  提示词只是提高了拒绝的概率。实际生产环境中，会结合细粒度的权限体系或工具级
  Cedar 策略（见第 09 章）作为兜底的安全措施。

## 8.8 晋级与资源清理

- **`晋级 ▸`**：停止 A/B，把 treatment 提示词写回 Agent。Agent 会自动发布新版本生效。
  
- **`清理`**：删除本次实验创建的配置包、临时 target、A/B 测试和在线评估配置

主指标方向为正时本章选`晋级`，晋级完成后执行`清理`。

### 可选：晋级后的回归对照

A/B 实验的流量全部是越权语料，在线判定只说明「对越权请求拒得更多了」，**没有测过新提示词
会不会误拦合法请求**——而 8.4 的补全恰恰是手工编写的拒绝规则，写得过宽就会把「我的 PTO
余额是多少」也一起拒掉。时间允许时，晋级后对 `lab-hr-zh-controls` 再跑一次批量评估
（三个评估器与第 07 章相同，约 6 分钟），与 7.7 的「改动前」结果配对：三项仍为 1.00 附近，
才能说明修复没有副作用。跳过这一步的代价是误拦风险未经验证。

> **必须执行清理**：未清理的实验占用共享实验网关，A/B 服务同一网关只允许一个活跃测试，
> 会阻止后续实验。共享网关本身不会被删除。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `实验能力` 为 `custom-source-unverified` | Agent 带上传的代码 | 用工具集重建 Agent，不要上传自定义代码 |
| `↻ 洞察 · 这些会话` 按钮不可点 | 选中的运行会话数不足 3（聚类下限），或同一批会话已有洞察在排队 | 核对选中的是 7.6 的 28 条基线运行；已在排队时等它完成即可 |
| 确认弹窗提示这些会话已有洞察结果 | 同一批会话重复发起洞察 | 直接用已完成的那次洞察运行，不要重复分析 |
| 就绪度停在`数据稀疏`，`尚未观察到的工具`非空 | A/B 语料只读工资单与 PTO，只覆盖两个工具 | 补跑 `lab-hr-zh-controls`（9 条），它触发政策、福利和 PTO 申请三个工具 |
| 就绪度为 `missing` | 所选回溯窗口内没有 trace | 先跑一次批量评估产生流量，再新建实验 |
| 自定义评估器在在线评估里不可选 | `指令 — 评审提示词`引用了真值占位符 | 删除 `{expected_response}` 一类占位符，只保留 `{context}` 与 `{assistant_turn}` |
| AI 推荐只覆盖了部分缺陷 | 优化器的 reward 信号是`目标达成率`一类通用指标，对泄露不敏感 | 在接受前的编辑框里补全条款，不要原样接受 |
| `RECOMMEND` 长时间 `RUNNING` | 标题的 `RUNNING` 指实验生命周期，不代表推荐任务已触发；推荐生成本身是异步操作 | 核对面板有无 `◐ 运行中…` 字样：有则继续等待，不要反复点按钮；没有则重新点击 `生成 AI 推荐`；明确报错后再重试 |
| 数据集下拉选中了别的数据集 | 默认选中列表第一个可回放数据集 | 发送流量前核对显示的是 `lab-hr-zh-ab (28)` |
| 在线评估记录数长时间为 0 | 前几分钟属于预期，记录常在 8–15 分钟时一次性出现 | 核对 `sent 28 · failed 0`，让 `▸ 监控结果` 继续轮询 |
| 记录数达不到`会话数 × 评估器数` | 部分会话未产生评估记录 | 以实际记录数为分母读均值，不要按会话数折算 |
| 横幅显示`统计显著`，主指标 `Δ` 很小 | 横幅按各指标加权平均，一升一降的两个指标互相抵消 | 只读主指标那一行的均值与 p 值 |
| 判定为`无显著差异` | 样本量不足以排除偶然，属正常结局 | 按面板给的三条路选：补流量重启、主观晋级（有确认弹窗）或清理保留现状 |
| 新建实验返回 409，或后续实验创建失败 | 上一次实验未清理，占用共享实验网关 | 执行`清理`，或等上一个实验出判定；共享网关本身不会被删除 |
