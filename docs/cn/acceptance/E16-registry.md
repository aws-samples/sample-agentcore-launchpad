# E16 Registry 「注册中心」 (section `registry`, `/v2/registry`) — acceptance standard

**Risk score:** 10 (R9 authorization drift: member-operable lifecycle next to the admin-only system Skill; R2 upstream: git/url acquisition, S3 bundle upload; `git-install` changes host state) → negatives ≥ 6 (this sheet lists 19) · **Recorded build:** to fill (host `GET /api/health`) · **Status:** draft

## 1. Scope and roles
- **Routes (`backend/app/core/route_policy.py`):** `GET /api/registry/records`, `…/records/search`, `…/records/discoverable`, `GET/PUT/DELETE …/records/{record_id}`, `GET …/{record_id}/live-agent-card`, `POST …/{record_id}/action`, `POST …/{record_id}/reimport`, `POST /api/registry/records` (register MCP / inline skill), `POST …/skills/import`, `GET …/skills/capabilities`, `POST …/skills/capabilities/git-install`, `POST …/sync-defaults`, `GET …/import-gateway/preview`, `POST …/import-gateway`, `GET …/attachables` = `MEMBER`; `POST /api/registry/skills/inspect` and `POST /api/agent-skills/import` = `perm:agents.deploy`. All workspace-scoped (`X-Workspace`).
- **Roles:** `demo-admin` registers `hr-onboarding-checklist`, approves it, imports Gateway targets; `hr-intern` (member) registers / submits their own records, is read-only on the system-managed architect Skill (`v2-registry-member-readonly`). Records are **shared** in both visibility modes (`users-and-ownership.md` §7 "CN decisions"); only the A2A record of a hidden agent disappears. Lifecycle of a system-managed Skill (`system_key` preset) is administrator-only; its content is never editable here.
- **Out of scope:** `POST /api/registry/a2a-demo` and the A2A demo views (removed in round 13, N13-obs6, `cn/r13-c`); Skill Lab training / evaluation internals (E15) — only the "evaluate from the record" entry point is observed here; Gateway target CRUD (E07 / case 19).
