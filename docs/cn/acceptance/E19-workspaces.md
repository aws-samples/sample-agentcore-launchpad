**Risk score:** 10 (R9 authorization: isolation leak across members, grant boundary; R10 admin self-service on hub-global rows; the module is **read-only in the video** by user ruling 2026-10-16 §7-4, but the API surface below is fully in scope for acceptance) → negatives ≥ 6 (this sheet lists 16) · **Recorded build:** to fill (host `GET /api/health`) · **Status:** draft

## 1. Scope and roles
- **Routes (`backend/app/core/route_policy.py`, all `WORKSPACE_EXEMPT` = hub-global):** `GET /api/workspaces` = `MEMBER` (returns only the caller's workspaces, `all_workspaces false`, no `role_arn`); `POST /api/workspaces`, `GET …/hub-identity`, `POST …/preflight`, `PATCH/DELETE …/{id}`, `POST …/{id}/purge`, `POST/GET …/{id}/bootstrap`, `GET/PUT …/{id}/grants`, `GET/PUT …/{id}/settings/visibility` = `ADMIN`. Cross-module: `PUT /api/settings/model-providers/workspaces/{id}/models` (E21) feeds the per-workspace model matrix shown here; `GET /api/capabilities` (`MEMBER`, workspace-scoped) is where the matrix becomes observable.
- **Workspace resolution for every scoped route (`routers/workspaces.py`):** `X-Workspace` header → admin without header lands on `default`; a member with exactly one grant needs no header; several grants → `400 workspace.header_required {available}`; no grant → `403 workspace.forbidden`; unknown id → `404 workspace.not_found`; a member asking for an ungranted workspace → `403 workspace.forbidden` (the member is **not** told which role reaches it). A workspace whose `bootstrap_status != ready` serves reads only (`409 workspace.not_ready` on writes) — except `default`, which is never gated.
- **`resource_visibility` rules (`services/visibility.py`, contract `users-and-ownership.md` §7):** `shared` (default; absent / unknown reads as shared) = every member sees every resource of the workspace. `isolated` = a member sees a row only when `created_by` is NULL (legacy, presets, config admin, resources made outside the console), their own `users.id`, or the id of a user whose **current** role is admin (admins act as publishers). Admins and the config admin see everything. A deleted creator's rows are admin-only. A hidden id answers the kind's **existing** not-found (never 403). The two step-1 member rules (own API keys, own chat sessions) hold in both modes. Policies, MCP / skill records, gateways and Connections stay shared. The setting is re-read with the workspace row on every request — a flip applies to the next request, migrates nothing, deletes nothing.
- **Live facts (default host, 2026-10-16, deploy-ops-2 T17, register N12-obs50/51):** the `default` workspace was flipped to **`isolated` and kept so**; verified with `demo-admin` + a second member account `hr-viewer` (password only in SSM `launchpad-hr-viewer-password`): datasets / chat / observability by-id routes answer 404 for the other member's rows, `DELETE` of a hidden agent is 404 not 403, legacy NULL-creator agents stay platform-visible. Recording E19 therefore starts from `isolated`; chapter ② flips nothing in visibility.
- **Roles:** `demo-admin` reads the detail, edits the model matrix, runs the `view=new` wizard to the validation step and **cancels**; `hr-intern` lists only granted workspaces and gets 403 on every admin route.
- **Out of scope (video):** creating, bootstrapping, deleting or purging a real second workspace (cross-account spoke; no second CN account); user approval / grant from the Users side (E18 AC-03). Both remain **in scope for API acceptance** below with hermetic evidence.

## 6. Failure classification
This module is ledger-only except `hub-identity` / `preflight` (one `sts:GetCallerIdentity` / `AssumeRole` each) and the bootstrap job. ENV: STS throttling or a hub role without credentials (`502 workspace.hub_identity_unavailable` is the product answering correctly); a `registered` test workspace left behind by an aborted run (clean with `purge`, as case 13 does). TEST: asserting `resource_visibility "shared"` on `default` (it is `isolated` since 2026-10-16); reading the matrix through a cached `/api/capabilities` from another workspace header. Everything else PRODUCT — in particular any 403 where the contract says 404 for a hidden resource, any `role_arn` in a member response, and any `external_id` or `resources` in any response.
