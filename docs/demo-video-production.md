# Demo video production

- **Narration default.** Use Microsoft Edge TTS Mandarin male **Yunyang**
  (`云扬`, `zh-CN-YunyangNeural`; the user's `云杨` means this voice), unless the user
  requests another voice. The existing recordings use `--rate=+4%`; adjust pacing
  to the scene. A voice preference alone is not a request to regenerate old videos.
  Narration tooling and billable AWS demo runs / S3 / CloudFront are separate costs.
- **Show the entry path before a completed example.** Follow the user's supplied
  URL and case. For the architect assistant, first record clicking **New
  Conversation** and typing a requirement, then explicitly introduce the previously
  completed elder-care AI application. Do not imply that historical output was
  generated by that new draft or submit it again solely to recreate existing results.
- **Record real actions and their outcomes.** Use the running UI and actual AWS
  results. Reuse an already running evaluation, wait for completion, then record
  scores, explanations, and traces. When asked for a complete experiment, show the
  actual baseline, configuration/candidate review, A/B execution, results, and
  experiment-resource cleanup. State errors, partial coverage, and insufficient
  evidence honestly; do not claim a winner or promote one without support and scope.
  Read the runbooks before any stack restart; recording must not interrupt live jobs.
- **Follow the current feature behavior.** Inspect the UI before scripting. For the
  architect assistant's step 03, include the Runtime twin → baseline → experiment
  flow and show the active `-rt` twin as the chat/evaluation/experiment target. Retain
  the source Harness and distinguish temporary experiment resources from the user's
  agents. Reuse existing conversion/experiment footage when editing narration alone;
  do not recreate billable resources just to obtain the same shot.
- **Keep revisions editable.** Store each revision under
  `data/videos/<feature>-<revision>/`, with storyboard, scene timings, raw captures,
  original TTS audio, rendering scripts, and result evidence. Before regenerating,
  compare and preserve the user's edits to `narration.zh-CN.txt` and opening titles;
  merge them into the source script before packaging can overwrite the export.
  Re-record only affected chapters, preserve the others, and recalculate subsequent
  chapter/subtitle offsets. Keep on-screen titles, narration, and captions in sync.
- **Prevent the known stereo echo.** Start from the original TTS audio and explicitly
  map exactly one narration stream into each clip and final video; do not also mix
  the browser audio or a previous narrated export. FFmpeg may negotiate stereo before
  applying a delay: `adelay=200` delays only the first channel. Use
  `adelay=delays=200:all=1` (or equal per-channel delays). The proven filter is
  `loudnorm=I=-16:TP=-1.5:LRA=7,aresample=48000,adelay=delays=200:all=1,apad,atrim=duration=<seconds>`.
  Repair affected clips from the source audio; downmixing the echoed stereo does not
  remove the duplicate speech. Check both channels and listen across chapter joins.
- **Capture and render for readability.** Use a consistent 1920×1080 viewport,
  readable Chinese text, and visible click/type/scroll actions. Wait for UI
  transitions to settle; trim long idle waits without changing the sequence or
  implying instantaneous cloud work. Use ASS/libass with a verified Chinese font
  for overlays/subtitles; the previous `drawtext` + TTC font attempt failed. Export
  an H.264/AAC MP4 with `+faststart` and a WebM fallback for browsers lacking H.264.
- **Anchor guidance to the actual element.** Prefer a temporary CSS outline on
  the target, restoring its previous outline before clicking or navigating.
  Viewport coordinates from `boundingBox()` must not be reused as absolute CSS
  coordinates inside a zoomed overlay: at `zoom: 1.2`, that scales the callout a
  second time. Static overlays can also linger after their target moves. Verify
  visible outlines against the target in captured and encoded frames, including
  scrolling and any final crop/zoom; an API-success check alone misses this drift.
- **Verify the delivered media.** Decode the final files, check duration and exactly
  one audio stream, and verify zero left/right narration offset. Inspect the opening,
  changed chapters, joins, and ending in a real browser, including seeking and
  subtitle timing. Deliver the video with poster, narration text, SRT/WebVTT,
  chapter metadata, and a working preview/player link. Keep generated media out of Git.
- **Publish through the shared video library.** Follow
  [Video library](video-library.md) and `scripts/publish_videos.mjs`.
  Use the existing private S3 / CloudFront deployment and a new immutable revision
  path; all environments share URLs in `frontend/src/config/videos.json`. Do not use
  expiring URLs or create a media stack per environment. Update duration, chapters,
  bilingual metadata, captions, and poster together; verify CDN Range/CORS and
  playback in `/videos`. Media upload and application/catalog deployment are separate.
