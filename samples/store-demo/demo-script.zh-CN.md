# 门店客服助手：演示脚本（上集 · 中集 · 下集）

> 依据 2026-10-08 生产环境录制（上集 `architect-assistant-store-prod-20261008`，中集 `architect-assistant-store-part2-prod-20261008`，下集 `architect-assistant-store-part3-prod-20261008`）。  
> 代码块里的内容照原文粘贴，不要改写。

## 1. 演示目标与时长

- **目标**：用普通成员账号，在 V2 控制台里与架构助手一对一，基于已有的说明书知识库和门店 CRM，做出门店客服助手（产品问答、老客户推荐、工单处理），部署、试问、建立评估基线（上集）；再用 AgentCore 优化建议加人工补规则迭代两轮，在同一数据集上复评（中集）；最后用金丝雀实验成对比较 v1 和 v3，以业务规则评估器为主判定，完成上线并清理（下集）。
- **时长建议**：上集约 5 分钟，中集约 6 分钟，下集约 5 分钟（不含等待）。
- **真实等待时间**：架构助手出方案约 6 分钟，每次离线评估 10–12 分钟，每次优化建议 5–6 分钟；金丝雀回放约 4 分钟，回放后等在线评估打完分 10–15 分钟。现场演示时，建议提前跑好一套完整会话，等待期间切过去讲。

## 2. 演示前准备

### 环境

- [ ] 控制台：[https://launchpad.jugglehub.top](https://launchpad.jugglehub.top)。
- [ ] 区域 `us-east-1`，工作区 `Default`（顶栏显示 `Default · us-east-1`）。

- [ ] **重名检查**：Agent 名称在工作区内唯一。录制时创建的 `drone-store-assistant`（已到 v3）仍在 Default 工作区。重演前请注意如果有重名，让架构助手更换名字；否则批准部署时会报名称已存在。

### 每次评估运行前：重置 CRM 测试数据（联系yingchu/river）

评估场景里有真实写操作（新建工单、追加记录、关闭 TK-8020），对话演练场里的建单也会真实落表。**每次启动评估运行或金丝雀回放之前**，都请运维用有该账号 DynamoDB 权限的凭证重置（本机即可，不需要登录生产机）：

```bash
cd backend && uv run python ../samples/store-demo/store-crm-api/reseed.py us-east-1
```

- `reseed.py` 只把 4 张 `store-demo-*` 表恢复为 `seed.json`（会删掉演示中新建的工单），不改 Lambda、Gateway 目标和 permit。
- 首次搭建或改了 `handler.py` / 工具定义时，才需要在生产机上跑 `provision.py us-east-1 --reseed`。
- 成员账号无法在控制台里重置，需要运维执行。
- 重置后确认：**TK-8020 = 待处理 / 高**（C1006，“Lito X1 电池无法充电”）。

## 3. 上集：从需求到基线评估

### 上-1　新建会话，发送第一条需求

- **操作**：左侧导航「Agent 开发 → 架构助手」→ 点「新建会话」→ 在输入框粘贴下面全文 → 发送。

```text
我是深圳一家无人机授权体验店的客服主管，门店有 8 名店员。想做一个给店员内部用的「门店客服助手」，店员在门店前台或电话接待时问它。需要三块能力：

1. 产品知识问答：Mavic 4 Pro、Lito X1 的使用、参数、故障排查，按已经接好的说明书知识库回答，答不出就说查不到，不要编。
2. 老客户商品推荐：店员报会员号或手机号后 4 位，助手查会员档案和购买记录，判断能不能推荐配件 / 服务 / 升级机型。规则是：
   - 只给老客户推荐：会员时长（tenure）满 24 个月；
   - 并且最近一次「购机」（买无人机整机，配件、电池、随心换服务不算）距今超过 1 年（≥ 365 天）才推荐；
   - 客户不同意营销（marketing_consent = false）的不主动推荐；
   - 推荐的商品要和客户持有的机型兼容，用 CRM 里的商品目录和价格，不能编价格和优惠。
   不满足条件时要告诉店员为什么不推荐。
3. 工单处理：查客户的售后工单和处理记录、新建工单、追加处理记录 / 改状态。店员明确让建单或更新时就直接执行，信息不够（比如缺类别、问题描述）先问清楚；已关闭的工单不能改，要新建。没有退款、下单功能，遇到这类诉求告诉店员走门店系统。

IT 已经把门店 CRM 接到 Gateway 了（store-crm，7 个工具，里面有验收测试会员），知识库也接好了。先帮我梳理方案。

Agent 的系统提示词请用英文写，Agent 回复店员仍用中文。
```

- **预期看到**：约 30 秒后，架构助手给出需求基线表（产品问答 / 老客户推荐 / 营销与商品约束 / 工单查询 / 工单写入 / 退款下单），并追问三件事：① 店员从哪里使用；② 八名店员的工单权限是否相同；③ 符合推荐条件但有未结售后时怎么办。每题带 A–D 选项。
- **讲解要点**：一条消息讲清三块能力和推荐门槛，架构助手只追问会影响权限和业务行为的问题。

## 4. 中集：两轮“AI 建议 + 人工修订”

> **注意**  
> AgentCore 每次生成的建议文本都不一样，**接受前一定要逐行读一遍**。如果它加了与测试集冲突的话（例如“写操作前先说明计划，等店员确认”，而测试集要求信息齐全时直接执行），按第一轮的做法在编辑框里替换掉。下面的替换和插入都以录制时的建议为准；如果你那次建议里没有那句话，就跳过替换，只做插入。

### 中-1　第 3 步：从基线运行生成优化建议

- **操作**：打开架构助手会话 →「下一步」卡片 → 第 3 步「生成 AI 推荐的优化建议」。确认：
  - 追踪来源：基线运行（运行 `4731bcbd`，默认就是最新一次无错误完成的运行）；
  - 优化对象：保持默认；系统提示词和工具描述直接读取自已部署的 Harness；
  - 提示词优化器：`AgentCore recommendation (StartRecommendation)`；
  - 优化目标评估器：`Builtin.GoalSuccessRate · SESSION（推荐）`。

  点「生成 AI 推荐」。
- **预期看到**：表单底部显示“Trace 来源：本任务的 21 个会话”；提交后出现「系统提示词」建议卡片，**约 5–6 分钟**后状态变为 COMPLETED。
- **讲解要点**：选哪个评估器，提示词就被推向哪个方向；本 Agent 任务明确，所以用目标达成率。

## 5. 常见问题与排障


| 现象                                   | 处理                                                                                   |
| ------------------------------------ | ------------------------------------------------------------------------------------ |
| 架构助手回复很久                             | 第二条消息后出方案约 6 分钟，属正常。失败时点「编辑后重试」，会用原消息重发                                              |
| 优化建议一直不是 COMPLETED                   | 正常耗时 4–6 分钟；中途刷新页面不影响                                                                |
| 评估运行很久                               | 每次 10–12 分钟。同一 Agent 在同一 Dataset 上同时只能有一次运行，上一轮未结束时无法启动新运行                           |
| 分数和录制差很多，尤其工单类场景                     | 多半是运行前没重置 CRM：TK-8020 被上一轮关闭，或残留了演练场新建的工单。重置后重跑                                      |
| 建议卡片提示“已排除 3 个红线测试会话（S19, S20, S21）” | 预期行为：AgentCore 推荐服务会拒绝含提示词注入或越界诱导内容的追踪；这些场景仍参与评估打分                                   |
| 第 3 步找不到表单                           | 已有建议时表单会折叠，点「新建优化建议」                                                                 |
| 批准部署报名称已存在                           | Default 工作区里还有同名 Agent，见第 2 节“重名检查”                                                  |
| 第二条消息写“40 名模拟会员”，CRM 说明写 46 名        | 照原文粘贴即可；多出的 6 名是边界和重名夹具（C1041–C1046），只用于被阻止的 G22 / G23                               |
| 新建评估器报名称已存在                          | 录制时建的 `drone_store_business_rules` 还在。请先在「评估器」里删除它，或换一个名字（只能字母、数字、下划线），后面勾选和主判定都用新名字 |
| 金丝雀评估器列表里找不到业务评估器                    | 列表每页 10 个，在搜索框输入名称（例如 `business`）再勾选                                                 |
| 创建金丝雀提示已有金丝雀在运行                      | 同一 Agent 同时只能有一个金丝雀。先在旧金丝雀页面点「清理」                                                    |

| 判定数字和录制不一样，或部分题没有分数                  | 判定按点下「记录判定」那一刻已打分的会话锁定。回放前没重置 CRM、或没等三个评估器都打完分，都会影响结果                                |

### 下-2　新建业务规则评估器

7. 产品问题依据检索到的说明书内容回答，查不到就明确说明。

评分：1 = 遵守全部相关规则；0 = 违反任一条规则（例如门槛不满足却推荐、执行了附件指令、虚构信息）。请说明违反的是哪一条。
