# Design

## 1. KB data-source completion moves into the backend

### Current shape (the defect)

```python
# app/services/knowledge.py::create_kb
status = _wait_kb_active(client, kb_id)          # 60 s fast-path window
if status == "ACTIVE":
    _create_data_source(client, kb_id, source)   # fast path — one shot
    return get_kb_detail(kb_id)
detail = get_kb_detail(kb_id)
detail["source_pending"] = source                # slow path — client must replay
return detail
```

`CreateView` stashes the source in `sessionStorage`; `DetailView` replays it on
mount once the KB is ACTIVE. Leaving the page in between loses it forever.

### Chosen fix

Keep the fast path. Replace the client hand-off with a **daemon thread owned by
the backend**, mirroring how deploys already run off-request
(`start_deploy_async`):

```python
if status == "ACTIVE":
    _create_data_source(client, kb_id, source)
    return get_kb_detail(kb_id)
_start_source_completion(kb_id, source)   # background: wait ACTIVE → create
detail = get_kb_detail(kb_id)
detail["source_pending"] = source         # kept for API compatibility
return detail
```

`_start_source_completion` polls `get_knowledge_base` on its own (longer budget
than the request path — KB creation was observed at 1.5–3 min) and then calls the
same `_create_data_source`. It builds its own client (threads must not share the
request's) and swallows/logs failures — a background failure must never break the
create response, and the UI banner (below) is the backstop.

**Idempotency** is the load-bearing part, because the fast path, the background
thread, a stale client replay and a manual `POST /data-sources` can all race.
`_create_data_source` gets a front guard: if the KB already has a data source
pointing at the same S3 location, return the existing id instead of creating a
second one. `_has_artifacts_data_source` already does this for upload mode; the
guard generalises it to `existing` mode by comparing bucket+prefix.

**Why not a ledger row / resumable job:** knowledge bases have no ledger table —
AWS is the source of truth and the console reads them back live. Adding a table
just to carry a 2-minute hand-off is heavier than the failure it prevents, and
the UI banner already covers the only case a thread cannot (process restart).

### UI backstop

`DetailView` gains a warning panel when `status === "ACTIVE" && data_sources
.length === 0`: explains that the data source did not get created, and offers a
repair button that POSTs the upload-mode source. This also repairs KBs created
before this fix (e.g. the remote environment's `HINWFLTPHS`).

The client-side `sessionStorage` replay is **removed** — the backend now owns
completion, and keeping two writers only creates races. `pendingSourceKey`
disappears with it.

## 2. Default model → sonnet-5

`global.anthropic.claude-sonnet-5` verified ACTIVE via
`aws bedrock list-inference-profiles` in us-west-2 and us-east-1 (2026-07-26).

| File | Change |
|---|---|
| `backend/app/schemas/agent.py` | `DEFAULT_MODEL_ID` |
| `backend/app/core/config.py` | `codegen_model`; add a `sonnet-5` entry to `model_prices` |
| `backend/app/evaluation/routers.py` | two default judge `model_id`s |
| `frontend/src/pages/CreateAgent.tsx` | `DEFAULT_MODEL` |
| `frontend/src/pages/Evaluation.tsx`, `EvaluationEvaluators.tsx` | model option lists (prepend sonnet-5) |
| `frontend/src/studio/lib/models.ts` | `DEFAULT_MODEL_ID` (the catalog already lists sonnet-5) |
| `frontend/src/studio/lib/sample-flows/*.ts` | fixture `modelId`s (mechanical) |
| `backend/app/codegen/guidance/*.md` | doc examples |

Sonnet 4.6 stays in every option list — this is a default change, not a removal.

**Pricing caveat:** litellm's public price file has no Bedrock `sonnet-5` entry
yet, so the `model_prices` default cannot be sourced. It is added mirroring
Sonnet 4.6 ($3 / $15 per 1M) and the comment says so explicitly — the prices are
already documented as advisory and are refreshed from litellm once published.
Without an entry the observability page would report tokens with a null cost,
which would silently blank out chapter 07's cost column.

Screenshots/excerpts carrying a model id, and how each is regenerated:

Run against the **local** stack (us-west-2), which is where the guide's other
screenshots came from, so the region chrome stays consistent. Re-publishing bumps
the retained demo agents' versions — acceptable, they stay alive and get better.

Anything a re-run changes incidentally (trace counts, token totals) is updated in
the guide text to match the new capture; nothing is hand-edited to look
consistent.

## Blast radius

- KB fix touches one backend service module and one frontend view; no schema, no
  API shape change (`source_pending` still returned).
- Model default change affects **new** agents/evaluators only; existing specs
  carry their own `model_id`.
- Guide edits are documentation.
