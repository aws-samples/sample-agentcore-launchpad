### Findings

1. **Unknown URLs render a blank page.** `App.tsx` (S3) nests every page under `<Shell>` but has no `path="*"` route, so `/nonexistent-route` (or any stale bookmark such as an old sub-route) renders nothing inside the router — S2 shows only the background grid: no sidebar, no topbar, no message, no way back. Inference: users hitting a mistyped or outdated link think the console crashed. No recorded decision (S12).

2. **An unreachable backend looks like an empty account.** With the API down (S4), the Overview reads "DEPLOYED AGENTS 0 · none yet" and "NO DEPLOYMENTS YET — CREATE YOUR FIRST AGENT"; Registry reads "NO RECORDS — IMPORT A GATEWAY OR REGISTER A RECORD"; Knowledge Bases "No knowledge bases yet"; Chat "no active agents — deploy one first"; Experiments "NO EXPERIMENTS". The code does this on purpose (`// backend offline — empty state`, S6), but the consequence is that the operator is told to create resources that already exist. Meanwhile the topbar chip shows a green LED and "ALL SYSTEMS GO" — it is a constant string (S5), never bound to `useHealth`, which itself swallows the error. The other half of the console (Memory, Observability, Users, Workspaces, Governance, Skill Lab, Datasets, Evaluators) already renders an error + retry, so the fix is consistency, not a new pattern.

3. **Small viewports overflow horizontally on half the pages.** A deliberate `@media(max-width:720px)` block turns the sidebar into a nav strip (S8), so narrow layouts are in scope. But the rule that makes tables scroll only matches `.panel > table`; tables inside `.pbody`, the `DataTable` empty wrapper `<div>`, or other containers (Create's existing-agents table, Users, Knowledge Bases, Registry) push the document to 410–787 px on a 390 px viewport (S7, `shots/en_narrow_*.png`). Additional offenders: the Registry toolbar row does not wrap and `.search` keeps `max-width:420px`; the Memory long-term actor `<select>` is as wide as its longest option; the Chat side panels' `.kv`/`.code` children lack `min-width:0`. On a phone or a split-screen tablet the page scrolls sideways and the sticky topbar's right end is unreachable.

4. **Stale copy and unlabeled controls (small).** The Chat trace rail placeholder still promises a trace rail "with Observability (Phase 9)" (S9) although Observability is nav item 07 and the trace rail itself is implemented (`Chat.tsx:293 loadTrace`); `onSuccessV` says "auto-register → Registry (phase 7)". Ten form controls (S10) have neither `<label for>`, `aria-label`, nor placeholder, so screen readers announce "combo box" with no name — the agent picker in Chat being the most-used one.

5. **In good shape.** No runtime console errors, no failed requests, no leaked i18n keys, en/zh-CN parity intact across 124 loads (S1). Loading feedback on the slow pages exists (S11). Empty states everywhere carry actionable copy. Long-job feedback (deploy pipeline) was not exercised — it needs a real deploy.

### Findings

1. **Disabled primary buttons do not say why.** Six forms (S1) gate their primary action on a boolean and dim the button (S2). Nothing marks required fields, nothing appears on hover, nothing changes as the user types until the button suddenly enables. On Register, the rule is "name matches `^[a-z][a-z0-9-]{2,63}$` and (MCP → URL starts with http, skill → SKILL.md non-empty)" — a user typing `Team Search` never learns why the button stays dead. The console already has the better pattern in Workspaces Create (button enabled, one explanatory line on submit) and a one-off `title=` hint in Agent Management (S3). A shared `disabledReason` on `Btn` would make the six consistent.

2. **Unknown ids on Knowledge Base detail and Registry edit produce raw HTTP 500s** (S4, S5). Cause: only assume-role `ClientError`s are handled globally (S7); KB detail hits `AccessDeniedException`, registry hits `ValidationException` (S6), so the console shows "HTTP 500" and the backend logs a traceback for what is a client-side bad id. Memory shows the same class of gap from the other side: a 502 whose message is the raw boto string (S4). The eval/agents routers do the right thing (S5), so the fix is the missing global mapping plus concise console copy, not per-route try/except.

3. **Stale deep links fail silently on Evaluation, Chat and Memory** (S4). `?ds=`, `?ev=`, `?oe=`, `?exp=` for an id that is not in the loaded list leave the URL as-is and render the unselected list; `/chat?agent=<gone>` silently selects the first active agent (the code comment says it drops the linked session so the wrong runtime is never posted to — good — but the user is not told). Skill Lab and Workspaces show the model copy ("That job no longer exists in this workspace — pick one from the table above.").

4. **zh-CN punctuation is inconsistent** (S8): 351 keys with half-width punctuation inside Chinese sentences next to 316 keys with full-width. Translation quality otherwise is good (no untranslated strings, no English-only values).

5. **In good shape**: unknown `?view=` values degrade to the default view; Workspaces / Skill Lab / Observability handle unknown ids well; the four merged directions are live on the host stack with no console errors during 39 page loads this run; no probe created AWS resources (S9).
